# Agent Console

Кроссплатформенный клиент удалённых агентов. Клиент открывает форму подключения. Быстрый демо-вход открывает чат с ожидающим подтверждения изменением. В демо-режиме черновики, история и разрешения живут в памяти MockTransport. В режиме «Сервер» история сохраняется в SQLite.

## Границы системы

- React 19, TypeScript strict, Vite, Tailwind CSS, Zustand и lucide-react. Общий фронтенд для Tauri v2, браузера и Telegram Mini App. Размещай общий UI в src/app. Храни состояние будущих экранов в Zustand.
- CLI агентов, платные API, учётные данные провайдеров и биллинг принадлежат серверу. Ключи запрещено включать в клиент, переменные VITE_ и хранилища браузера.
- src/protocol/types.ts описывает сериализуемые сообщения. UI работает через TransportAdapter. Сопоставление форматов конкретных провайдеров выполняет сервер.
- В src/app/runtime.ts выбирается реализация транспорта. Тестовые сценарии задаются при создании MockTransport. Макет генерирует события в памяти. Любой путь или команда в макете является демонстрационными данными.
- Будущий Go-sidecar отвечает за tsnet и локальный MCP. В Tauri открывай только необходимые разрешения. Вызовы read_file, edit_file, write_file, list_dir, grep_search, run_command передаются типизированными сообщениями.
- Привязки к Telegram размещай в src/platform. Обычный браузер и Tauri должны работать без Telegram. Учитывай узкую ширину и safe-area.

## Потоки и права

- У каждого ответа уникальный messageId. Собирай события по chatId и messageId в порядке seq. Дельты содержат очередной фрагмент. После done или error поток завершён. При уходе подписчика прерывай чтение через AbortController и освобождай подписки.
- События аккаунта приходят по отдельной подписке. Квоты зависят от провайдера. Время сброса передаётся в миллисекундах Unix.
- Сопоставляй вызов и результат по callId, запрос разрешения и решение по requestId. Пока решение ожидается, операция приостановлена. Разрешение для папки в mock действует в пределах текущего экземпляра, чата, устройства и вида операции.
- Проверку доступа read/fork/write, привязки устройств, доверенных папок, квот и hard limit в рабочей системе выполняют сервер и соответствующий исполнитель MCP. Решение UI само по себе прав не предоставляет.
- MockTransport поддерживает scenario со значениями normal, refusal, error, quota и delayMs для тестов. Режим chat выдаёт Markdown. В режиме mcp меню «Сценарии MCP» подставляет примеры для всех шести инструментов. Файлы хранятся в памяти MockTransport отдельно для каждого устройства и общие для чатов с доступом к нему. Подписка аккаунта получает снимки квот и входящий запрос от демо-пользователя.

## Демо-сессии

- Учётные записи demo, alex и maria используют учебный пароль demo и строку Base64 от mock://agent-console. Смена пользователя через выход и вход в том же окне позволяет проверить выдачу прав. Перезагрузка страницы сбрасывает учебный сервер.
- Права на чат и привязки устройств проверяет MockWorkspace внутри транспорта. Для доверенных команд требуется write и явно выбранный владельцем доверенный режим. Доверие ограничено конкретным чатом, получателем и устройством, где выдан доступ. Отзыв устройства снимает связанные разрешения.
- Выход завершает сессию GUI. Привязанные демо-устройства могут оставаться онлайн как независимые MCP-исполнители.

## Проверки

- Основная среда запуска и проверки проекта — Docker (`docker compose up -d --build`, веб-клиент на `http://127.0.0.1:3000`, бэкенд на `http://127.0.0.1:8080`). После любых изменений кода обязательно пересобирай и перезапускай соответствующие сервисы в Docker (`docker compose up -d --build web` для фронтенда, `docker compose up -d --build backend` для Go-сервера или `docker compose up -d --build` целиком) и проверяй работу именно в Docker-стеке (на Windows при отсутствии `docker` в `PATH` используй `"C:\Program Files\Docker\Docker\resources\bin\docker.exe"`).
- npm ci устанавливает зависимости из lock-файла. npm run dev открывает Vite на 127.0.0.1:1420 (используется только при отладке вне Docker). npm run build проверяет TypeScript и собирает dist. npm test проверяет контракт транспорта.
- npm run tauri dev запускает десктопное окно на машине с Rust и системными зависимостями Tauri v2. Успешную веб-сборку и проверку нативного приложения фиксируй отдельно.
- Для изменений UI открой рабочее приложение, пройди основной сценарий на десктопной и узкой ширине. При исправлении ошибки воспроизведи и повтори тот же сценарий.

## Go-сервер

- Запускай команды Go из `server/`. Модулю нужен Go 1.26 или новее. `cmd/server` содержит HTTP-сервер и CLI для создания пользователей, `internal/config` читает конфигурацию, `internal/httpapi` обслуживает REST, `internal/store` отвечает за SQLite и миграции.
- Создай локальную учётную запись командой `go run ./cmd/server create-user --username demo --password 'demo-password'`. Пароль в примере предназначен для локального тестирования. Храни пароль в базе как bcrypt-хеш, а токен устройства как SHA-256.
- Запуск для локальной разработки — `SERVER_ADDR=127.0.0.1:8080 go run ./cmd/server`. Проверка — `curl http://127.0.0.1:8080/api/health`. Для тестов используй `go test ./...` или `CGO_ENABLED=0 go test ./...`.
- Переменные из окружения имеют приоритет над `server/.env`. Значения по умолчанию — `SERVER_ADDR=:8080`, `DB_PATH=./data/app.db`, `PROVIDER=stub`, `CODEX_BIN=codex`, `CORS_ORIGIN=*`. Для доступа из Интернета используй HTTPS и задай точный origin клиента. Для локального запуска держи сервер на loopback. Миграции выполняются автоматически при запуске.
- REST использует JSON. Для входа отправляй `POST /api/auth/login` с `username`, `password`, `deviceName`. Защищённые маршруты принимают `Authorization: Bearer <token>`. `POST /api/chats` принимает объект с необязательными `title` и `model`, а выдача истории требует владения чатом. Типы REST описаны в `src/protocol/types.ts`.
- WebSocket `/ws?token=...` принимает `RunRequest` с `target.mode: 'chat'` и отправляет `RunEvent` с `chatId`, `messageId` и возрастающим `seq`. Не записывай query string этого маршрута в логи. При конкурентном запросе в тот же чат сервер возвращает `chat_busy`. После переподключения получи историю через REST. `done` означает, что ответ уже сохранён.
- `internal/provider` содержит StubProvider и CodexCliProvider. Stub работает локально без аккаунта. Для проверки с реальным CLI задай `PROVIDER=codex`, укажи установленный `CODEX_BIN` и настроенную на сервере авторизацию Codex. CLI запускается из `server/data/workspaces/<user_id>` с отключёнными shell, веб-поиском и плагинами. ID сессии хранится в SQLite и используется для `codex exec resume`. Клиентские `history` не передаются в CLI. Повтор ответа на другой модели через `retryOf` пока остаётся демо-функцией.
- Запусти фронтенд командой `npm run dev` из корня. На экране входа выбери «Сервер», оставь `http://127.0.0.1:8080` и войди учётной записью, созданной через `create-user`. Режим и адрес меняются на экране входа и в настройках. Смена сервера завершает текущую сессию.
- `src/transport/RemoteTransport.ts` реализует REST, сокет и автоматическое переподключение. В `localStorage` хранятся режим, адрес и токен текущего устройства. После сбоя сокета клиент перечитывает историю и не отправляет уже переданное сообщение повторно. `runId` в истории связывает запрос и ответ даже после переподключения. Другие открытые клиенты подтягивают готовый ответ по `done`.
- В серверном режиме доступны личные чаты в режиме «Только чат». MCP, шеринг и биллинг остаются сценариями MockTransport.
- Серверный каталог моделей загружается с авторизацией через `GET /api/models`. Codex-провайдер запрашивает видимые модели через `model/list` установленного CLI и кэширует каталог на минуту. `StubProvider` возвращает пустой список. Демо-режим использует свой каталог.
- Для чтения локальных чатов Codex укажи `CODEX_HISTORY_USERNAME` равным логину владельца в Agent Console. Без этой настройки индекс выключен. Сервер читает обычные и архивные чаты через локальный Codex App Server. История появляется в отдельном разделе «Чаты Codex» и доступна для чтения. Строки SQLite и исходные сессии Codex при просмотре не переписываются.
